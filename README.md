# streamstats

Потоковый анализатор файлов событий. Читает CSV и JSONL построчно (файл целиком
в память не грузится) и строит JSON-отчёт со статистикой.

## Установка

```
pip install -e ".[dev]"
```

## Запуск

```
python -m analyze samples/ok.csv
python -m analyze a.csv b.csv --format csv --output report.json
python -m analyze samples/bad.jsonl --format jsonl --skip-invalid
```

Формат можно не указывать, в большенстве случаев он определится сам (`.csv`, `.jsonl`).
`--format` применяется ко всем входным файлам сразу. Без `--output` отчёт печатается в stdout(по умолчанию).

## Формат событий

Обязательные поля: `timestamp` (ISO 8601), `level` (DEBUG, INFO, WARNING, ERROR, CRITICAL),
`source` (непустая строка), `message` (строка, может быть пустой). -- Как в тз

CSV: первая строка это заголовок. JSONL: один JSON-объект на строку. -- Как в тз

## Отчёт

| Поле | Что это |
|---|---|
| `files` | обработанные файлы |
| `total` | общее число событий |
| `by_level` | события по уровням |
| `by_source` | события по источникам |
| `top_error_sources` | до 5 источников с наибольшим числом ERROR и CRITICAL |
| `first_timestamp`, `last_timestamp` | самая ранняя и самая поздняя метка (`null` для пустого входа) |
| `skipped_invalid` | сколько строк пропущено (только с `--skip-invalid`) |

Ошибкой в `top_error_sources` считается событие с уровнем ERROR или CRITICAL, текст сообщения не анализируется.
При равном числе ошибок источники сортируются по имени.

## Плохие строки

По умолчанию прекращает работу, выводит ошибку, код возврата 2, отчёт не пишется. С `--skip-invalid`: строка пропускается, в stderr пишется WARNING, счётчик попадает фиксирует пропуск.
